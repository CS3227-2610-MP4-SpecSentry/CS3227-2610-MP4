## Endpoint and audit decisions to confirm

1. **Reuse `POST /api/proposals`.** Current WorkingContent request requires `{title,problem,constraints,expectedBehavior,summary,diffText,criteria,evidence}`. Keep wire schema unchanged: four-field UI sends `summary:''`, `diffText:''`, `criteria:[]`, `evidence:[]`; no later-scope controls. Title/problem/expected behavior nonblank; constraints may be empty. Owner from session, DRAFT/version 0 and IDs from server. Existing response is `{proposalId,revisionId:null,workingRevisionId,assignmentId:null,assignmentVersion:null,state:'DRAFT',version}` with 201. Do not silently substitute `{id}` for `{proposalId}`.
2. **Reuse `GET /api/proposals/:id/draft`.** Existing response `{proposalId,workingRevisionId,version,state,content}`. Role and owner checks precede working-content lookup; another Contributor gets 403 without content; wrong roles denied, missing root 404. Existing generic `GET /api/proposals/:id` is a submitted-view interface and rejects never-submitted roots; do not replace its semantics. Keep existing owner-private detail eligibility rather than newly defining later lifecycle policy. Increment 1 only creates DRAFTs and has no other state-changing routes.
3. **Add `GET /api/proposals?limit&cursor`.** Proposed owner-only DRAFT collection. Strict query permits only limit (decimal 1–100; default 20) and bounded canonical cursor. Filter by authenticated owner, state DRAFT, never-submitted root (`currentRevisionId:null`, `firstSubmittedAt:null`); no client owner/state filters. Return `{items:[{proposalId,workingRevisionId,title,state:'DRAFT',version,createdAt}],nextCursor}`. Title comes from that owner's WorkingRevision JSON, never copied onto the submitted/public root. Query/order roots by `createdAt DESC,id ASC`; seek predicate earlier timestamp OR equal timestamp/greater ID, take limit+1. Fetch private JSON only for authorized page IDs. Existing WorkingRevision has no Prisma relation in the proposed schema, so use a bounded second query by those IDs, not an invented include relation. Missing/malformed working content fails safely; no silent skipping or raw body logs. Propose cursor scope `JSON.stringify(['owner-drafts',actor.accountId])`, timestamp=createdAt and ID tie-breaker using existing helpers; reauthorize each page. Cursor is not authority or a snapshot guarantee. Existing owner index suffices initially; no speculative performance migration.
4. **Fix DRAFT-SEC-003 and cover new list.** After successful authorization/query/response validation, write `SecurityEvent` inside the same business transaction: actorId from trusted actor, detail action `PROPOSAL_DRAFT_VIEWED`/target proposal ID; list action `PROPOSAL_DRAFT_LISTED`/target `own-drafts`; outcome `success`, correlationId from request, timestamp generated by DB. No title/body, cursor, returned IDs list, CSRF/session material or arbitrary metadata. These routine read events remain restricted operational evidence with existing 90-day retention, never ProposalActivity/timeline. Fail closed with safe error if audit cannot persist; expiry at transaction end still withholds content. Existing failed-operation/validation/role/CSRF audit paths stay intact. Confirm action naming/outcome convention and retention with audit owner. Successful creation retains atomic root + working JSON + DRAFT_CREATED business activity; business history never goes through operational pruning.
5. **Validation presentation.** Existing global SafeExceptionFilter drops fieldErrors. Prefer client-side same-schema field validation for adjacent accessible errors, retaining text, plus generic safe server errors with correlation ID; recheck strict validation server-side. Avoid copying tip `http.ts`, which imports the AI gateway. Confirm only if server fieldErrors are needed; no shared error contract mutation assumed.
