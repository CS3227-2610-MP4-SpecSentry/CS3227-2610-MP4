## Proposed settled contracts

1. `POST /api/proposals/:id/ai/patch-risk` is Reviewer-only, authenticated and CSRF protected. Strict request: `{revisionId, assignmentId, expectedVersion, expectedAssignmentVersion, selectedCriterionIds}`. Version fields extend the integration AI payload consistently with the shared stale-write invariant. IDs preserve exact spelling; selected IDs are 1–5 unique IDs of the latest revision. Reject browser prompt, actor, endpoint, model and all unknown fields. No idempotency response cache.
2. A short `businessTransaction` validates actor/session/account, assignment ID/version, proposal version, latest submitted revision and IN_REVIEW/CHANGES_REQUESTED before selecting context. Select the complete immutable submitted summary, problem/constraints/expected behavior, all criteria with required flags and identifiers, complete sanitized unified diff, all evidence and same-revision evidence links needed for grounding. Include only proposal/revision/assignment identifiers and selected criterion IDs needed for provenance. Exclude working content, human histories, identities not needed for grounding and previous AI data. Context construction is a distinct typed projection, not the general detail DTO.
3. `PatchRiskContext` and `PatchRiskScope` are server-only immutable values. `AiGateway.analyzeReviewer(context, scope, signal)` accepts server configuration and injected `AiTransport`, `VerifiedTokenCounter`, clock and bounded scheduling interfaces through DI. No provider/model secrets cross into shared browser contracts. Gateway returns validated `ReviewerRiskResult` plus safe metrics; never a raw envelope. Persist no result or recoverable receipt containing suggestions. Test transport is injected only by test bootstrap; browser flags cannot select it.
4. Before every outbound attempt, recheck current actor/session/access/assignment and revision in a fresh short transaction after queue wait. Abort locally on loss or outdated initial context. Recheck again after provider completion before disclosure. Loss of account/session/assignment or withdrawal discards output. Drop/reclaim never revives an old assignment even for the same reviewer.
5. New revision is distinct from drop: add a server-only immutable `ReviewAssignment.accessGenerationId`. Claim creates a fresh random generation; retained-reviewer resubmission copies it exactly. Drop, disablement and withdrawal end that generation permanently; any later claim creates a fresh value even for the same reviewer. Existing assignments receive unique values in migration; pre-feature in-flight AI does not exist. Capture the value in server-only PatchRiskScope. Final disclosure requires fresh enabled actor/session/current assignment, same proposal/reviewer/generation and eligible lifecycle. Revision change under the same generation permits STALE/NEW_REVISION only. Never infer continuity from timestamps, UUID order, reviewer identity or a partial history query. Ineligible lifecycle rejects output. Same-revision version drift may return STALE/REVIEW_CHANGED, without enabling application. Denial responses carry no suggestions. Foundation owns schema/migration; integration owns claim and retained-submit creation/projection paths.
6. Strict success envelope: `{status: 'CURRENT'|'STALE', staleReason: null|'NEW_REVISION'|'REVIEW_CHANGED', analyzedScope: {proposalId, revisionId, assignmentId, expectedVersion, expectedAssignmentVersion}, selectedCriterionIds, result}` with discriminated status/reason validation. Exact runtime role result is normative AI-SECURITY-SPEC, including code-point lengths, exact selected coverage, duplicate-key rejection before parsing, bounded nesting, unknown-field rejection and severity-stable sort. Transport requires exactly one assistant string choice, stop finish, no refusal/tool/function result, <=64 KiB body and valid optional usage when supplied. No repair or validation retry.
7. Safe fallback uses documented 422/429/503 and safe error codes/reasons with correlation ID; no submitted text, provider body or secret in any error. The existing safe exception filter must expose an allowlisted AI_UNAVAILABLE/reason mapping without returning raw exception objects. `Retry-After` is bounded and safe. Manual forms remain mounted and usable while AI is pending or fails; do not reuse the workspace-wide manual-mutation busy lock for the network call.
8. UI holds suggestions only in mounted page state. Request generation + AbortController prevents late responses after selection/navigation/logout; clear state on access loss, pagehide and revision/assignment change, including BFCache restoration handling. Cleanup explicitly erases the unsaved AI-prefilled finding form, captured source coordinates and callbacks as well as the suggestion panel, so Back cannot recover a prefilled raw risk. Tests exercise each surface. Ordinary independently authored manual form content is preserved during AI failure. No local/session storage, service worker/query persistence, URL encoding, response caching, telemetry bodies, HTML insertion or auto-combination across batches. Display analyzed revision, selected IDs, not-analyzed criteria, advisory/confidence text and rerun variability. React plain text renders all hostile output. STALE has no Create finding action.
9. Create finding opens an editable human form prefilled with severity/description and optionally one selected criterion; risks with multiple IDs require explicit criterion choice or none. Cancel performs no request. Explicit Save uses the existing strict `POST .../findings` and the original analyzed proposal/revision/assignment versions. Never rebind old suggestions to refreshed coordinates. Existing deterministic transaction rechecks fresh account/session/role/root/assignment/lifecycle/versions; finding + version + activity commit together. ## Gateway controls and proposed persistence

Foundation owns new append-only safe AI request/attempt records and durable quota/queue records. Request and outbound attempt/retry identities remain distinct. Store only actor/scope IDs, template version, hash of normalized redacted context, timestamps, latency, outcome/error-class allowlists, attempt ordinal, selected-criterion count and provider-reported validated usage (null if absent). Never raw input/output, provider errors, prompts, reasoning or credentials. Operational retention is 90 days, separate from business history and short quota windows. `GET /api/proposals/:id/ai/audit` returns own bounded safe metadata only after fresh current access; other actors, shared activity and reassignment projections never receive it.

Only approved HTTPS SoCLaaS host/base routes; redirects rejected, no tool calls or streaming. Fixed versioned system template with structured delimited untrusted input; delimiter escaping and representative injection evaluation. Secret detection runs before any call across every allowed context field: high-confidence credentials/private keys reject; lower-confidence recognized secrets redact before hashing/counting. Redaction must not silently drop fields or truncate content. Unsupported sanitation fails closed. Empty optional constraints/evidence retain their actual meaning.

Reject complete diff >20,000 code points and full input >10,000 verified tokens including template/identifiers/framing; reserve <=800 output and respect the verified model context minus framing. No estimated tokenizer enables live traffic. OPEN-002 evidence must bind exact alias, key-scoped catalog/context, parameter support (`max_tokens:800`, `reasoning_effort:none`, `stream:false`), verified token counter, provider quotas and retention policy. The checked local configuration contains placeholder key/model and no verified evidence; no live call is authorized by those placeholders. Mock counters/providers prove application mechanics only. Any later live compatibility stage uses synthetic non-sensitive probes and records its separate evidence.

Atomic multi-process reservation uses PostgreSQL serialization of a gateway quota coordinator in short independent transactions. Count every attempted dispatch, including retries and failures; do not count local preflight rejections. Enforce rolling user 10/10min, user 60/SGT day, global 30/minute, waiting queue cap 10. Queue leases expire after the overall 20-second deadline, clean up on cancellation/crash, and are distinct from active attempts. No business-root locks while waiting/networking. At most one retry for allowed transient errors, with bounded jitter and Retry-After within the same deadline; never retry validation/refusal/400/401/403 or ambiguous/exhausted-budget 429. An expired request cannot start another attempt. Reserve before dispatch; uncertain network transmission counts conservatively as an attempt. Atomic final-slot tests must prove no overspend. Provider UTC windows remain separate from application SGT reset.

One monotonic deadline begins at authenticated handler admission, before initial authorization/context retrieval. Pass a remaining-deadline contract through initial/final authorization, context retrieval, quota/queue database work, parsing and HTTP completion, in addition to AbortSignal on provider transport. Bound transaction acquisition/execution and PostgreSQL statement/lock waits by remaining time; the existing businessTransaction 5s maxWait/10s timeout defaults cannot independently consume the request budget. AI-specific bounded transaction options must preserve the existing account/session/root lock order and unchanged manual defaults. If remaining time expires, cancel transport, release queue leases, return safe fallback without suggestions; never return late success. Final failed-attempt metadata uses bounded independent cleanup without extending a successful response deadline. Tests deliberately block initial/final account/root/quota locks to demonstrate the complete request bound.
